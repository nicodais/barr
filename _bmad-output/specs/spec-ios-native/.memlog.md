- (direction) User: prepare Shamal for a native iOS build via Capacitor, wrapping the existing Vite/Three.js/Rapier web app rather than rewriting it
- (note) CLAUDE.md §11 previously listed Electron/Capacitor wrapping as a later-stage non-goal; that stage is now in scope, iOS only, for this spec
- (direction) User: full App Store submission is the v1 distribution target (TestFlight + App Store Connect listing + review submission), not just a working Xcode project
- (direction) User: add native haptics and native photo save/share as in-scope native extras; no other new native-only features
- (direction) User: Apple Developer Program enrollment and signing/provisioning setup are part of this epic's scope, not assumed pre-existing
- (note) src/input/Haptics.ts already exists and is web-Vibration-API-based; supported is hardcoded false on iOS since Safari has no navigator.vibrate — native haptics capability replaces that disabled path via Capacitor's Haptics plugin, reusing the existing priority/shape system rather than rewriting it
- (note) src/ui/PhotoBar.ts Save/Share currently use a Blob + <a download> link and navigator.share; both are unreliable inside a Capacitor WKWebView, so native save/share needs Capacitor's Filesystem/Share (or an equivalent Photos-save) plugin behind the same UI
- (note) src/input/TouchSource.ts already implements the iOS 13+ DeviceOrientationEvent.requestPermission() gesture-gated pattern for tilt-steer; needs verification (not a rewrite) inside the Capacitor local-scheme WKWebView, which has known quirks around permission prompts
- (note) No external asset fetches found in src/ (grep for https:// only matches credit-text strings and the GAME_URL constant); public/ is ~2.1MB, entirely local — confirms the app is packageable for fully offline native operation without an asset-loading redesign
- (note) public/ already has icon.svg, icon-192/512.png, icon-maskable.png, apple-touch-icon.png, and manifest.webmanifest from prior web/PWA-lite work — native iOS icon set and launch screen should derive from these existing marks, not commission new art
- (capability) CAP-1 Capacitor native shell: the existing Vite production build runs unmodified inside a Capacitor-generated iOS project, launching to the same driving experience on simulator and a real device. Success: vite build output loads inside the Xcode-run app with no blank screen, console errors, or missing asset, and gameplay (drive, dune-bash, rollover, POIs, settings) is reachable end to end.
- (capability) CAP-2 Offline-capable native bundle: the app launches and plays fully with the device in airplane mode once installed, since all gameplay assets are bundled locally rather than fetched from a remote origin. Success: a fresh install, network disabled, completes a full drive session with no failed asset load.
- (capability) CAP-3 Tilt-steer parity in the native shell: the existing DeviceOrientationEvent-based tilt control (with its iOS permission-request flow) works inside the Capacitor WKWebView the same way it works in mobile Safari. Success: on a real device, the one-time orientation permission prompt appears and, once granted, tilt steering responds during a drive.
- (capability) CAP-4 Native haptics: rollover, landing, texture, and UI haptic cues (already defined in src/input/Haptics.ts) fire via a native haptics call on iOS instead of being silently disabled. Success: Haptics.supported is true on a native iOS build and a rollover produces a felt haptic pattern on a real device.
- (capability) CAP-5 Native photo save/share: Photo mode's Save action writes the captured image into the device's real Photos library, and Share opens the native iOS share sheet, instead of relying on a download link or navigator.share. Success: tapping Save on a real device produces a new entry in Photos; tapping Share opens the native share sheet with the captured image attached.
- (capability) CAP-6 App icon and launch screen: a full native iOS icon set (all required sizes) and a launch screen are supplied, visually derived from the existing icon.svg/apple-touch-icon.png marks and consistent with CLAUDE.md's flat-shaded warm-palette visual style. Success: the installed app shows a correctly rendered icon on the home screen at every size Xcode requires, and a launch screen appears with no default-white flash.
- (capability) CAP-7 Safe-area and native chrome correctness: HUD, menus, and the touch control cluster respect iOS safe areas (notch/Dynamic Island, home indicator) and an appropriate status-bar style, distinct from the responsive web viewport handling already in place. Success: on a notched device, no HUD element or touch control is clipped or obscured by the safe-area insets in either orientation the app supports.
- (capability) CAP-8 Apple Developer Program enrollment and signing: an Apple Developer Program membership, App ID/bundle identifier, and development + distribution signing certificates and provisioning profiles are set up. Success: Xcode archives and signs a distribution build with no signing error.
- (capability) CAP-9 TestFlight beta distribution: a signed build is uploaded to App Store Connect and made available to internal testers via TestFlight. Success: an internal tester installs and runs the build through the TestFlight app.
- (capability) CAP-10 App Store Connect listing and submission: store listing metadata (name, description, keywords, screenshots for required device sizes), the privacy nutrition label, and the required privacy manifest are prepared and the app is submitted for App Store review. Success: the app reaches 'Waiting for Review' or better status in App Store Connect with no rejected-for-missing-metadata error.
- (constraint) Architecture spine AD-1 through AD-7 (composition-root-only wiring, sibling systems exchange state via type-only imports, src/data/* stays inert, single physics clock, GameSettings/Progress as the only shared localStorage blobs, activeRegion as region source of truth, all control schemes resolve to SteeringInput/ThrottleInput/BrakeInput) remain binding; native plugin calls (haptics, filesystem/share, orientation) must be added behind the existing input/haptics/photo module seams, not imported directly into gameplay code
- (constraint) CLAUDE.md §4 visual style (flat-shaded, low-poly, warm limited palette, no PBR realism) governs app icon and launch screen art direction the same as in-game art — no photoreal or glossy iOS-style icon treatment
- (constraint) GameSettings/Progress localStorage persistence (architecture AD-5) must survive inside the Capacitor WKWebView's storage origin across app relaunches and app updates, not just within a single session
- (constraint) NFR-2's already-validated 60fps mobile target (PRD, Epic 1, closed 2026-09-07) must not regress under WKWebView rendering; a real-device frame-rate spot-check inside the native shell is required rather than assumed equivalent to mobile Safari
- (constraint) No monetization, in-app purchase, or push-notification capability may be introduced as part of App Store submission prep — CLAUDE.md states no monetization, and none of these were requested
- (non-goal) Android/Google Play build is out of scope for this epic, even though Capacitor supports it
- (non-goal) Electron/desktop wrapper is out of scope, per CLAUDE.md's own later-stage framing
- (non-goal) New gameplay content (vehicles, POIs, regions, narrative lines) is out of scope; this epic is packaging/platform work only
- (non-goal) Monetization, in-app purchases, and push notifications are out of scope
- (non-goal) A rewrite or architectural change to the existing web app is out of scope; Capacitor wraps the existing static build as-is
